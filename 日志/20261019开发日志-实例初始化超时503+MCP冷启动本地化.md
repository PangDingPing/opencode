## 1. 背景与根因回顾

2026-10-19 上午排障：Docker 容器 `yejian-v0.1.8` 会话页面发起会话无反应，后台报 `EPIPE: broken pipe`（fd:45 / syscall:send / errno:-32）。

根因链：

1. 全局配置的 browser MCP 用 `npx -y @playwright/mcp` 启动，npx 每次启动都向 npm 官方源发元数据校验请求
2. 官方源极不稳定（实测 3 次 ETIMEDOUT 重试 + 偶发成功 ≈ 80 秒），首次下载长达数分钟
3. 实例冷启动期间首个用户请求无限等待，用户中止连接 → 服务端写 socket 失败 → EPIPE

当日已完成的第一阶段修复：npm 源切 npmmirror + MCP 版本固定 0.0.83（全新用户首条消息响应从数分钟降至 8.97s）。本批改动是结构化收尾：**本地缓存化（层1/层2）+ 超时兜底（S1）**。

## 2. 实施内容

### 层1：npx `--prefer-offline`（运维配置，已生效）

`E:\AI\AIworkbench-data\root\.config\opencode\opencode.jsonc`（`/root` bind mount 进容器）：

```jsonc
"command": ["npx", "-y", "--prefer-offline", "@playwright/mcp@0.0.83", "--cdp-endpoint=http://192.168.1.81:9081"]
```

原理：`/root` bind mount 使 npx 缓存持久化在宿主机；npx 默认每次发 registry 元数据校验请求（304 revalidation），弱网下这是 ETIMEDOUT 来源；`--prefer-offline` 缓存命中即用，跳过校验。

### S1：实例初始化等待者超时（代码）

新文件 [instance-init-timeout.ts](file:///d:/AI/opencode/packages/opencode/src/project/instance-init-timeout.ts)：

- `InstanceInitTimeoutError extends Schema.TaggedErrorClass`（字段 `directory`、`waitedMs`）——TaggedErrorClass 自带 `_tag`/`toJSON`/`pipe`，满足 Effect Error 接口要求（首版普通 Error 子类在 acp/directory.ts typecheck 失败）
- `instanceInitTimeout()`：读 `OPENCODE_INSTANCE_INIT_TIMEOUT_MS`，非法值回退默认 60_000

[instance-store.ts](file:///d:/AI/opencode/packages/opencode/src/project/instance-store.ts)：

- `waitWithTimeout` helper：`Deferred.await` + `Effect.timeoutOrElse({ duration, orElse: () => fail(new InstanceInitTimeoutError(...)) })`——**只限制等待者**，Deferred 本身与 bootstrap fork 不受影响；超时后缓存条目保留，重试命中同一 Deferred，初始化完成即成功
- load（两处等待点）/reload（一处）接入
- provide 实现：`catchTag("InstanceInitTimeoutError")` → `Effect.logError` + `Effect.die`——后台/测试路径无人处理超时失败，消化为 defect，泛型 E 不扩大（workspace.ts / fixture.ts 的类型错误随之消解）
- Interface.provide 声明保持纯 `E`（曾误写 `E | InstanceInitTimeoutError` 导致 fixture 类型错误）

[instance-context.ts](file:///d:/AI/opencode/packages/opencode/src/server/routes/instance/httpapi/middleware/instance-context.ts)：HTTP 边界映射——

- `InstanceInitTimeoutError` → `HttpServerResponse.jsonUnsafe({ message: "环境正在初始化（已等待 N 秒），请稍后重试；输入已恢复。" }, { status: 503, headers: { "Retry-After": "10" } })`
- 必须用 `jsonUnsafe` 保证 application/json content-type，否则前端拿到裸状态码
- 前端链路（已验证）：SDK `wrapClientError` 提取 `body.message` → submit.ts `errorMessage` → `showToast` + 回滚乐观消息 + 恢复输入框

[lifecycle.ts](file:///d:/AI/opencode/packages/opencode/src/server/routes/instance/httpapi/lifecycle.ts)：`markInstanceForReload` 的后台 reload 加 `catchTag`——等待者超时记 `logWarning` 后视为完成（无 HTTP 响应可承载）。

[directory.ts](file:///d:/AI/opencode/packages/opencode/src/acp/directory.ts)：ACP loader 边界把超时转 `ServiceFailureError`（ACP 错误协议是封闭 union，不能透传新错误类型）。

## 3. 踩坑记录

1. **Effect v4 `Effect.catch` 类型签名是整体替换错误通道**：`<E, A2, E2, R2>(f: (e: E) => Effect<A2, E2, R2>)` 的 E2 不合并原 E；在泛型混合通道（`E | 具体错误`）上收窄推断不可靠 → 改用 `Effect.catchTag`（类型级 `ExcludeTag` 移除匹配 tag，剩余错误保留），一次通过
2. **Interface 声明与实现不同步**：provide 实现已消化超时后，typecheck 仍报 fixture/workspace 错误——根源是 Interface.provide 声明还写着 `E | InstanceInitTimeoutError`，改回纯 `E` 即消解
3. **本机 `bun serve` 静默退出**（exit 1 无任何输出，含 --print-logs）：仅发生在当前 PowerShell 工具链下；`Server.listen` 直启完全正常。冒烟改用临时脚本 `smoke-server.ts` 直启（已删除）。此问题与本次改动无关（干净工作区同样复现），后续如需本机调试 serve 可沿用直启方式
4. **bootstrap.run 不卡 MCP**：各 service init 的慢活都 `forkScoped` 自管，bootstrap 只等 materialization——本机找不到自然慢源。冒烟改用 `OPENCODE_INSTANCE_INIT_TIMEOUT_MS=1` 极小超时直接验证超时→503→重试成功的机制链路（等效验证，不依赖慢源注入）
