# Docker 镜像 v0.1.7：技能面板更新打包 + Alpine 源换华为云

## 需求背景

1. 技能面板（党群文章分组）需随 `E:\AI\YEJIAN\.opencode\skills` 目录调整而更新：
   - 「公文排版」由 `document-format` 切换为 `gov-doc-format`（tooltip 补充「严格遵循 GB/T 9704-2012（及 GB/T 33476.2-2016）和环保集团公文标准」）
   - 原占位的「党建文章」（developing:true）改名为「公文写作」，启用 `chinese-official-writing`
2. 构建 v0.1.7 镜像时，原阿里云 Alpine 源 gcc 下载仅约 61KB/s，18 分钟停滞无输出，疑似卡死；诊断后发现是网速极慢（buildkit 在 Docker Desktop Linux VM 内执行，宿主机日志缓冲不可靠）

## 备选方案

- 技能切换：直接改 `packages/app/public/yejian/skills.json`（前端资源，编译进后端二进制），无需其它代码改动
- 构建加速：a) 耐心等阿里云慢速下载（gcc 包 45MB / 60KB/s ≈ 十几分钟，整个工具链 400MB+）；b) 换国内快速镜像源；c) 改在服务器/其它网络构建。实测后选 b——华为云 3.4MB/s 比阿里云快约 55 倍

## 影响范围

- 仅镜像产物与技能面板配置；前端资源嵌入后端二进制，需重建 binary 生效（`-RebuildBuilder`）
- Alpine 源换华为云只影响镜像构建速度，不影响运行逻辑

## 踩坑记录

1. **Edit 工具重写 `.ps1` 会丢 UTF-8 BOM**（历史已记录）：本次第 2 次遇到。BOM 丢失后 PS 5.1 按本地 GBK 误读中文注释 → 吞行 → 语法错误。修复：用 `[System.Text.UTF8Encoding]::new($true)` 重写补回 BOM，并验证前 3 字节 `EF BB BF`。教训：编辑 `.ps1` 后必须验证 BOM 保留
2. **构建"卡死"实为网速极慢**：初始 log 停在 `Installing gcc` 18 分钟无增长，判停滞。诊断（curl 测各镜像 gcc 下载速度）发现阿里云仅 61KB/s，切换华为云 3.4MB/s 后全部 58 个系统包 46 秒装完。buildkit 在 Desktop VM 内执行、宿主机 stdout 缓冲，无法实时观观察进度
3. **8088 端口被旧容器占用导致 build.ps1 容器启动段失败**：构建脚本只删同名 `yejian-v0.1.7`（本不存在），旧 `yejian-v0.1.6` 继续占 8088。解决：先 `docker stop/rm yejian-v0.1.6`，再 `run.ps1 -ImageTag v0.1.7` 启动
4. **v0.1.6 与 v0.1.7 标签历史均指向同一 merge 提交** `41c54f629c`（"sync"），未反映真实版本号——打 v0.1.7 标签前需先清理旧指向
