# 20260711 开发日志 — 前端 dev proxy 后端端口改回默认 4096

## 需求背景

启动后端命令是：

```
bun run --no-cache --conditions=browser ./src/index.ts serve --port 4098
```

`--port 4098` 是为了配合前端 `packages/app/vite.config.ts:29` 写死的 `const backend = "http://127.0.0.1:4098"`。
这个 4098 是 v.1.17.6 多用户分支之前的人改的，dev 分支默认是 4096。
opencode serve 的默认端口是 4096（`CONTRIBUTING.md:105` 明示），所以 `--port 4098` 是非必要的覆盖。

## 备选方案

1. **改 vite.config.ts:29 把 4098 改回 4096**——和 dev 对齐，前后端都用 4096 默认，启动命令可省 `--port 4098`。
2. **改 opencode serve 的默认端口为 4098**——大量侵入式改动（grep 出来至少有 4-5 处需要 4096 → 4098：CONTRIBUTING.md、github/index.ts:233、sdks/vscode、docker 等），且违反"少改上游文件"原则。
3. **不改任何代码，启动命令继续用 `--port 4098`**——保持现状但每次启动都得多敲 17 个字符。

选了方案 1：单文件、单行修改，跟 dev 一字不差，未来合并上游 v0.1.196+ 无冲突。

## 文件改动

| 文件 | 改动 |
| --- | --- |
| `packages/app/vite.config.ts` | L29: `4098` → `4096` |

## 影响范围

- 前端 dev (`bun dev` from packages/app) 启动后，proxy 默认转发到 4096 后端
- 后端启动命令可简化为 `bun run --no-cache --conditions=browser ./src/index.ts serve`（去掉 `--port 4098`）
- 跟 dev 默认行为完全一致

## 验证步骤

1. 终端 A：`cd packages/opencode && bun run --no-cache --conditions=browser ./src/index.ts serve`
   期望：`opencode server listening on http://127.0.0.1:4096`
2. 终端 B：`cd packages/app && bun dev`
   期望：前端 dev 起来后，浏览器开 3000 端口的页面，发起 API 请求能正确转发到 4096 后端
3. `git diff dev -- packages/app/vite.config.ts` 无差异
