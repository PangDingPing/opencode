# 20260711 开发日志 — v0.1.6 多用户分支适配 Schema.Defect()

## 需求背景

回退到 v0.1.1（commit `a7c8f38a5`）并新建分支 `v.1.17.6多用户` 后，启动后端立刻报错：

```
TypeError: undefined is not an object (evaluating 'ast.encoding')
  at D:\AI\opencode\packages\llm\src\schema\errors.ts:205:17
  at D:\AI\opencode\node_modules\effect\dist\SchemaAST.js:2559:7
  ...
```

错误位置是 `Schema.optional(Schema.Defect)` 这种写法。仓库内 effect 是 `4.0.0-beta.74`，
而 v0.1.1 时代的代码沿用旧 effect（beta 74 之前）的 `Schema.Defect` 常量用法。

## 根因

`Schema.Defect` 在 effect 4.0.0-beta.74 改成了构造函数：

```ts
// 旧（v0.1.1 / 上游 beta 74 之前）
export const Defect: Schema.Schema<...>  // 直接当 schema 值用

// 新（beta 74+）
export declare function Defect(options?: ErrorOptions): Defect  // 必须调用
```

错误是：`optional(Defect)` 内部对 `ast` rebuild 时，effect 期望 `ast.encoding` 存在
（因为 `Defect` 现在是 transform schema `decodeTo<Unknown, typeof Json>`），
但 Defect 实际返回的是 `Unknown` schema 的 ast（无 `encoding`），
导致 `toType(ast)` 访问 `ast.encoding` 时崩。

## 备选方案

1. **直接给所有 24 处加 `()`**——跟上游 commit
   `4f1ae1604 chore: upgrade Effect to beta 83 (#32340)` 完全一致（该 commit 同步修改了
   26 个文件的 `Schema.Defect` 写法）。改动小（每处一个括号）、不引入抽象、不升 effect 版本。

2. **升级 effect 到 beta 83**——一次解决，但 beta 83 之后还有其他 breaking changes
   风险，且 lock 文件会变。

3. **写 polyfill/shim**——`packages/core/src/effect/defect.ts` 重新导出
   `Defect = Schema.Defect()`，但需要改 24 个 import，改动面更大。

选了方案 1：跟 dev 分支 24 个文件的修法一一对应，**复制了上游的修法**，
未来 v0.1.196+ 合并时这些文件跟上游一致，冲突面最小。

- **启动链路修复**：`opencode serve` 在 v0.1.6 era 仓库下能正常起服
