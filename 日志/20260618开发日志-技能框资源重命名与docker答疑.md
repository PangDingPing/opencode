# 一、网页端技能框资源 ASCII 重命名（fix）

## 1.1 前置操作

无（沿用 6-15 已创建的 `update-logo` 分支，未切换；本地工作树干净）。

## 1.2 现象

v0.0.3 docker 部署后，浏览器打开 `http://localhost:8088/new-session`，页面 console 报错：

```
SyntaxError: Unexpected token '<', "<!doctype "... is not valid JSON
```

DevTools Network 显示 `/yejian/技能.json` 返回 200 但 body 是 `<!doctype html>...`；`技能库.png` 同样 200 但 body 是 HTML，`<img>` 自然显示破图。

## 1.3 根因

[packages/opencode/src/server/shared/ui.ts:69](file:///d:/AI/opencode/packages/opencode/src/server/shared/ui.ts#L69) 的查找逻辑：

```ts
const file = embeddedWebUI[requestPath.replace(/^\//, "")] ?? embeddedWebUI["index.html"] ?? null
```

- `requestPath` 来自 `new URL(request.url, "http://localhost").pathname`，**保留 percent-encoded 形式**（`/yejian/%E6%8A%80%E8%83%BD.json`）
- `embeddedWebUI` 字典的 key 是**未编码的中文**（`yejian/技能.json`）
- 浏览器自动 percent-encode URL → 二者对不上 → fallback 到 `index.html`（2479 字节 HTML）→ JSON.parse 报错；`<img src>` 同理拿到 HTML，破图

证据：在 154MB 的 `dist/opencode-linux-x64-baseline-musl/bin/opencode` 二进制里直接搜，能找到 `yejian/\u6280\u80FD.json":uc,"yejian/\u6280\u80FD\u5E93.png":mc`（文件已嵌入二进制，只是 key 形态跟请求对不上）。

> 顺便确认：源文件 `packages/app/public/yejian/技能.json` 和 `技能库.png` 本身没问题（hash 一致，553 个文件中包含 `yejian/技能.json` 和 `yejian/技能库.png`）。

# 二、opencode web 用户名、密码设置（答疑）

## 2.1 答案

`packages/opencode/src/server/auth.ts:17-20` 定义了**HTTP Basic Auth** 的环境变量：

```ts
export class Config extends ConfigService.Service<Config>()("@opencode/ServerAuthConfig", {
  password: EffectConfig.string("OPENCODE_SERVER_PASSWORD").pipe(EffectConfig.option),
  username: EffectConfig.string("OPENCODE_SERVER_USERNAME").pipe(EffectConfig.withDefault("opencode")),
}) {}
```

行为：

- **不设 `OPENCODE_SERVER_PASSWORD`** = 不启用认证（容器启动时打印 `OPENCODE_SERVER_PASSWORD is not set; server is unsecured.` 警告）
- 设了 `OPENCODE_SERVER_PASSWORD` = 启用 Basic Auth，浏览器访问时弹"输入用户名密码"对话框
- 用户名不设默认 `opencode`

## 2.2 设置方法

编辑 `D:\AI\opencode\docker\api-keys.env`，追加 2 行：

```env
OPENCODE_SERVER_USERNAME=你的用户名
OPENCODE_SERVER_PASSWORD=你的密码
```

重启容器即可生效（**不需要重 build 二进制**，纯环境变量）：

```powershell
powershell -ExecutionPolicy Bypass -File D:\AI\opencode\docker\run.ps1 -EnvFile "D:\AI\opencode\docker\api-keys.env"
```

# 三、docker 部署源代码修改是否实时生效（答疑）

## 3.1 答案

**不会实时生效。** 当前的 docker 部署是"预编译 + 烤进镜像"模式，不是开发模式。

## 3.2 原因

[docker/Dockerfile:47](file:///d:/AI/opencode/docker/Dockerfile#L47) 用 `COPY` 把**编译好的二进制**烤进镜像：

```dockerfile
COPY packages/opencode/dist/opencode-linux-x64-baseline-musl/bin/opencode /usr/local/bin/opencode
```

这个 154MB 二进制是**自包含**的：
- 整个 `packages/opencode/src` 编译进了二进制
- 整个 `packages/app/dist`（包括 `skills.json`、`skills-panel-icon.png` 等 553 个文件）**嵌入**在二进制里（前面排查时已经看到二进制里有 `yejian/skills.json → uc` 这样的 key-value）

而 [docker/run.ps1:50-58](file:///d:/AI/opencode/docker/run.ps1#L50-L58) 挂载的 3 个目录都是数据目录，**没有挂载源代码**：

```powershell
-v "D:\AI\AIworkbench:/workspace"          # 用户工作目录
-v "D:\AI\AIworkbench-data\root:/root"     # 容器 root 家目录
-v "D:\AI\AIworkbench-data\tmp:/tmp"       # 临时目录
# 没有：-v D:\AI\opencode\packages\app\src:/app/src
```

所以源代码修改**不会**在容器里实时生效；改完要看到效果必须重跑 `build.ps1 -ForceRebuild`（15-30 分钟，编译占大头）。

## 3.3 实时生效的办法：本地 dev 模式

按 [packages/app/AGENTS.md](file:///d:/AI/opencode/packages/app/AGENTS.md) 跑 dev 模式（不依赖 docker）：

```powershell
# 终端 1：后端
cd D:\AI\opencode\packages\opencode
bun run --conditions=browser ./src/index.ts serve --port 4096

# 终端 2：前端（Vite dev server 自带 HMR）
cd D:\AI\opencode\packages\app
bun dev -- --port 4444
```

浏览器开 `http://localhost:4444`：
- 前端代码改动 → Vite HMR 自动刷新（秒级）
- 后端代码改动 → Bun 自动重启（秒级）

## 3.4 两种模式定位

| | 本地 dev 模式 | docker 部署模式 |
|---|---|---|
| 谁在跑 | bun 源码进程 | 154MB 编译好的二进制 |
| 前端怎么服务 | Vite dev server | 后端从二进制里读 `embeddedWebUI` 返回 |
| 改前端代码生效时间 | 秒级（HMR） | 15-30 分钟（重 build） |
| 改后端代码生效时间 | 秒级（Bun 重启） | 15-30 分钟（重 build） |
| 用途 | 改代码看效果 | 给用户用、稳定跑 |

# 四、review-drawing-downloader skill 跑不通的问题（答疑）

## 4.1 现象

在 docker 容器里执行 `E:\AI\YEJIAN\.opencode\skills\review-drawing-downloader` 技能，提示"安装的是无图形界面的 linux，无法渲染出二维码"。

## 4.2 根本原因

该 skill 的核心工作流（见 [SKILL.md:42-49](file:///E:/AI/YEJIAN/.opencode/skills/review-drawing-downloader/SKILL.md#L42-L49)）：

1. 启动 Chrome 浏览器（[review_drawing_downloader.py:102](file:///E:/AI/YEJIAN/.opencode/skills/review-drawing-downloader/scripts/review_drawing_downloader.py#L102) 注释明确说"有头模式"）
2. 打开审图系统登录页 `http://120.197.38.55/`
3. **页面上显示二维码 → 用户用微信扫**
4. 用户按回车键告诉脚本"我扫完了"
5. 后续 selenium 自动跑

**这个工作流在 docker 容器里有 3 层根本矛盾**：

| 步骤 | docker 容器 | Windows 宿主机 |
|---|---|---|
| 启 Chrome | ❌ 镜像没装 Chrome / ChromeDriver（v0.0.3 装的是 LibreOffice / poppler / Node / Python，**不包含 selenium 也没有 ChromeDriver**） | ✅ |
| 显示二维码 | ❌ 容器是 server，没有"屏幕"——即使有 GUI 也是容器内部的虚拟 X server，**用户看不到** | ✅ |
| 微信扫码 | ❌ 没有二维码图片可扫 | ✅ |
| 按回车键继续 | ⚠️ 理论上可以 `docker exec -it` 进去按，但前一步已卡死 | ✅ |

## 4.3 换成 Ubuntu + 装 Chrome/ChromeDriver 行不行？

**仍然跑不通。** 换 Ubuntu + 装依赖只能解决"Chrome 启不起来"这一半问题，还有 3 个问题解决不了：

1. **二维码显示**：Ubuntu 容器的 X server 是容器内部的虚拟设备，**Windows 上看不到**。即使装 Xvfb 让 Chrome 启起来，二维码也只画在容器的虚拟 framebuffer 上。
2. **微信扫码**：二维码在容器里，用户没法扫。
3. **Cookie 持久化**：扫码登录后 Cookie 在容器内存，`docker restart` 后没了；挂载到宿主机的 Cookie 文件也经常因设备指纹/IP 绑定而跨环境失效。

## 4.4 解决方案（按推荐度排序）

### 方案 1（最简单）：直接在 Windows 宿主机跑，绕过 opencode

```powershell
# 宿主机 PowerShell
pip install selenium requests
python E:\AI\YEJIAN\.opencode\skills\review-drawing-downloader\scripts\review_drawing_downloader.py
```

前置：宿主机有 Python 3 + Chrome 浏览器 + `pip install selenium requests`。

### 方案 2：opencode 不在 docker 跑，改在 Windows 跑（参见 #三）

跑本地 dev 模式后，opencode 直接读 `E:\AI\YEJIAN\.opencode\skills\review-drawing-downloader`（Windows 路径）→ skill 跑在 Windows 上 → Chrome 启得来 → 你能看到二维码 → 能扫。

### 方案 3：把 skill 拆成"扫码"和"下载"两步

- `scripts/get_qrcode.py`（宿主机跑）：只负责启 Chrome → 打开登录页 → 截图保存到共享目录 → 退出
- `scripts/download_with_cookie.py`（容器里跑）：读 cookie 文件 → 直接进项目列表 → 下载

**限制**：很多政府/企业审图系统不支持 Cookie 复用（每次强制重新登录），这条路可能走不通。

### 方案 4（不推荐）：headless + 远程看截图

技术栈：Ubuntu + Chrome + Xvfb + Selenium headless + Python `http.server`。

- Xvfb :99 起虚拟显示
- Chrome `--headless=new --display=:99` 启起来
- 打开审图系统 → 截图二维码 → 保存到 `/workspace/qr.png`（挂载到宿主机）
- Python 起 `http.server 8089` → 浏览器访问 `http://<宿主机IP>:8089/qr.png` 看到
- 你扫完 → `docker exec` 进去按回车（或脚本加 polling 探测登录态）

**问题**：二维码 60 秒过期、polling 探测登录态要做、需要挂载端口（防火墙）——很折腾。

## 4.5 结论

**这个 skill 设计的就不是给"无人值守的 server"用的。** 工作流里"微信扫码"必须人工介入，而 docker 容器的本质就是"无人值守的 server 进程容器"。

推荐**方案 1**——直接放弃在容器里跑这个 skill，Windows 宿主机 PowerShell 跑；或者**方案 2**——把 opencode 也搬到 Windows 上跑（本地 dev 模式），二维码、扫码、回车都是 Windows 上自然的。
