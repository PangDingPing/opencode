# 2026-07-03 开发日志 - admin 用户管理功能完善

## 需求背景

admin 账户的"用户管理"页面（`/admin/users`）原仅显示实名白名单占位，无任何管理操作能力。后端 `User.Service` 已实现全部 CRUD 业务方法（createUser/listUsers/getUser/updateUser/changePassword/resetPassword/setDisabled/deleteUser），但未通过 HTTP 暴露。需要：
1. 新增 admin 路由组暴露 8 个 HTTP 端点
2. 重写前端页面为表格内联操作 UI
3. 补齐自保护（不能操作自己）与最后一个 admin 防护（不能删除/降级最后一个启用 admin）
4. 危险操作二次确认 + toast 反馈

## 备选方案

### 方案对比（前端 UI 形态）

| 方案 | 优点 | 缺点 | 选择 |
|---|---|---|---|
| 表格内联操作 | 沿用现有 users.tsx 表格结构，30 人规模一屏可见 | 操作菜单项较多时略挤 | ✅ 选用 |
| 详情页跳转 | 每个操作有独立页面，可放更多信息 | 多一次跳转，30 人规模过度设计 | ❌ |
| 卡片列表 | 视觉宽松 | 信息密度低，不适合管理场景 | ❌ |

### 方案对比（自保护实现位置）

| 方案 | 优点 | 缺点 | 选择 |
|---|---|---|---|
| 后端 handler 内 assertNotSelf | 安全兜底，前端绕过也拒 | 前端无即时反馈 | ✅ 后端必做 |
| 前端 DropdownMenu.Item disabled | 即时反馈，用户体验好 | 仅前端防护，可被绕过 | ✅ 前端必做 |

最终双端都做：后端兜底 + 前端即时反馈。

## 踩坑记录

### 坑 1：`Schema.nullable` 在 effect 4 中不存在

**现象**：`groups/admin.ts` 第 31 行用 `Schema.String.pipe(Schema.nullable, Schema.optional)` 报 `error TS2339: Property 'nullable' does not exist on type 'typeof Schema'`

**根因**：effect 4.0.0-beta.74 移除了 `Schema.nullable`，改用 `Schema.NullOr`

**修复**：参考 `packages/core/src/account.ts:28` 已有的 `Schema.NullOr` 用法，改为 `Schema.NullOr(Schema.String).pipe(Schema.optional)`

### 坑 2：`Effect.catchAll` 在 effect 4 中不存在

**现象**：`handlers/admin.ts` 3 处用 `Effect.catchAll((e) => Effect.fail(new InvalidRequestError(...)))` 报 `error TS2339: Property 'catchAll' does not exist on type 'typeof Effect'`

**根因**：effect 4 移除了 `Effect.catchAll`，错误转换用 `Effect.mapError`

**修复**：参考 `packages/llm/src/tool-runtime.ts:39` 的 `Effect.mapError` 用法，改为 `Effect.mapError((e) => new InvalidRequestError({ message: (e as Error).message }))`

### 坑 3：IconButton 的 `icon="more"` 图标不存在（导致操作菜单看不见）

**现象**：用户反馈"没有看见重置密码、禁用、踢下线、删除等按钮，无法点击"

**根因**：`Icon` 组件注册表（`packages/ui/src/components/icon.tsx`）共 95 个图标，**没有** `more` / `more-vertical` / `ellipsis` / `dots` 中的任何一个。运行时渲染 `<use href="#opencode-icon-more" />` 浏览器找不到对应 symbol，图标不显示，DropdownMenu 触发器变成空白不可见。

**修复**：参考项目里其他 5 处 DropdownMenu 触发器的惯例（layout.tsx / sidebar-workspace.tsx / file-tabs.tsx 等），统一用 `dot-grid`（横向三个圆点）作为"更多操作"图标。改 `icon="more"` → `icon="dot-grid"`。

### 坑 4：新增用户弹窗误从白名单下拉选用户名

**现象**：用户反馈"既然是新增用户怎么可能从白名单选用户？应该是新增全新的用户名"

**根因**：第一版 `admin-user-create-dialog.tsx` 把用户名做成了 `<select>` 下拉，从 `/api/auth/allowed-names` 拉白名单过滤已注册的作为选项。这与"新增用户"语义冲突——新增应该是创建全新的用户名。

**修复**：
1. 前端：`<select>` → `<input type="text">`，用户名手动输入
2. 后端：`createUser` 去掉 `isAllowedName` 校验，用户名可自定义
3. 移除前端白名单 fetch 逻辑（仅保留 `usedUsernames` 查重）

### 坑 5：预存的 effect 版本冲突错误干扰判断

**现象**：`bun typecheck` 在 `packages/server` 输出大量 `error TS2xxx`，涉及 `handlers/auth.ts`、`handlers/session.ts`、`handlers/admin.ts` 等多个文件

**根因**：项目 `node_modules` 里有多个 effect 版本（`effect@4.0.0-beta.74` vs 其他版本），TypeScript 类型推断在 `HttpServerResponse` / `[NodeInspectSymbol]` 等符号上冲突，是预存问题，非本次改动引入

**判断方法**：对比 `handlers/auth.ts`（未改动）和 `handlers/admin.ts`（本次新增）的错误模式完全一致，说明是同源预存错误，不是本次改动引入的新错误
