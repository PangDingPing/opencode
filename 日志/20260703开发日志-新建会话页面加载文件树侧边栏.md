# 新建会话页面默认加载文件树侧边栏

## 需求背景

用户反馈：新建会话页面（路由 `/new-session`）无法调出文件树侧边栏，希望实现新建会话页面默认加载文件树侧边栏。

## 问题分析

### 根本原因（三层）

1. **`new-session.tsx` 不渲染 `SessionSidePanel` 组件**
   - 文件原第 52-77 行的 JSX 只包含 `NewSessionDesignView` + `SessionComposerRegion`
   - 文件顶部注释明确说明：draft 页"no terminal, review pane, file tree, or message timeline"

2. **没有切换入口**
   - `new-session.tsx` 不渲染 `SessionHeader`（标题栏），所以没有文件树切换按钮
   - 不使用 `useSessionCommands`，所以没有 `Ctrl+\` 快捷键

3. **`SessionSidePanel` 自身有防御性判断**
   - `session-side-panel.tsx:216` 行：`<Show when={isDesktop() && !(settings.general.newLayoutDesigns() && !params.id)}>`
   - 当启用新布局且无 session id 时，整个 `<aside>` 不渲染

### 设计意图

draft 页是"轻量入口"，只放输入框让用户敲第一条 prompt。提交后才升级为真实 session，跳转到 `/:dir/session/:id`，此时才挂载完整侧边栏。

## 备选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 复用完整 SessionSidePanel | 在 new-session.tsx 渲染 SessionSidePanel，传空 review props，改防御判断 | 功能完整 | 需提供 11 个 props（全为空）、改 session-side-panel.tsx 防御判断、useSessionLayout 在无 params.dir 时行为不确定、改动大 |
| **B. 独立轻量文件树侧边栏（选定）** | 在 new-session.tsx 直接渲染 `FileTree` 组件 + 宽度手柄，复用 `layout.fileTree` 状态 | 最小改动、独立性强、不依赖 review 数据、不动现有 SessionSidePanel | 无 changes tab（draft 页无 review 数据，本就不需要） |

**选定方案 B 的理由**：
- 符合项目"最小改动原则"
- draft 页面没有 review/diff 数据，不需要 SessionSidePanel 的 review 功能
- 只需文件浏览能力，`FileTree` 组件已足够
- 所需 context 在 `DraftProviders` 中均已提供（`FileProvider`、`LayoutProvider`、`SettingsProvider` 都是全局的）

```tsx
let treeDir: string | undefined
createEffect(() => {
  const dir = sdk.directory
  if (!isDesktop()) return
  if (!layout.fileTree.opened()) return
  if (sync.status === "loading") return
  const refresh = treeDir !== dir
  treeDir = dir
  void (refresh ? file.tree.refresh("") : file.tree.list(""))
})
```

### 2. FileTree 组件 props 签名确认

担心 `FileTree` 组件的 props 签名不匹配，特意 grep 了 `export default function FileTree` 确认：

```tsx
export default function FileTree(props: {
  path: string
  class?: string
  ...
  onFileClick?: (file: FileNode) => void
})
```

`path` 和 `onFileClick` 都是可选/可传的，`class` 也是可选的，所以 `<FileTree path="" class="pt-3" onFileClick={() => {}} />` 完全合法。
