# 2026-07-11 开发日志：默认打开 /YEJIAN 项目

## 需求背景

系统入口问题：登录成功后停留在登录页（之前的 `props.onLoginSuccess` 回调只是 refetch，没有跳转）；首次登录改密成功后跳到 `/new-session`（空白新建会话页），用户还要再点一次"添加项目"才能进项目目录。

目标：让用户**登录后或首次改密后，自动进入 `/YEJIAN` 项目**，省掉中间步骤。同时 Docker 部署要把 `D:\AI\AIworkbench\YEJIAN` 目录挂载为容器的 `/YEJIAN`，让前端 `/${base64Encode("/YEJIAN")}` URL 能解析到实际项目目录。

## 备选方案

### 方案 A：使用 `useNavigate` + createEffect 检测"刚登录"

- 在 `auth.tsx` 加 createEffect 监听 `me()` 变化，结合 sessionStorage 标记"刚登录"实现导航
- 优点：SPA 内导航，性能好
- 缺点：状态机复杂（要区分"刚登录" vs "刷新页面"，需要 sessionStorage 协调）

### 方案 B：window.location.href 整页刷新（采用 ✅）

- 登录/改密成功后直接 `window.location.href = defaultProjectHref`
- 优点：逻辑简单、状态干净、复用现有 change-password 的 `window.location.href` 模式
- 缺点：整页刷新，比 SPA 导航略慢；但登录/改密后本来就是重大状态切换，可接受

### 方案 C：服务端 redirect

- 后端登录接口返回 302 + Location 头
- 优点：更标准
- 缺点：需要改 backend，scope 太大；前端还得处理改密场景

**采用方案 B**，与 change-password.tsx 现有的 `window.location.href = "/new-session"` 模式一致。

### 3. `git clean -fd` 误删重要目录（**本轮核心事件**）

用户在 `git reset --hard HEAD` 之后，回复"也清掉"，执行 `git clean -fd`。但 `git status` 默认**不显示未跟踪目录**（要加 `-uall` 才显示），所以前一条 git status 输出**不完整**，以下重要目录被一起删除且无法恢复：

| 路径 | 影响 |
|---|---|
| `代码/` | 项目规则约定的"代码文件存放目录" |
| `packages/opencode/admin/` | 可能是多用户 admin 模块代码 |
| `packages/opencode/scripts/` | 自定义脚本 |
| `packages/opencode/上官尤/` | 中文名个人工作目录 |
| `.empty_tmp/` | 临时目录 |

**教训**：
- 执行 `git clean -fd` 前应该用 `git clean -fdn`（dry-run）先看会删什么
- 或者用 `git status -uall` 看完整未跟踪文件
- 危险操作前必须确认
- **本次默认项目功能不依赖被删的代码**，独立可工作；但用户需知会团队成员

### 4. Recycle Bin 不可访问

尝试用 `Shell.Application` COM 对象和 `C:\$Recycle.Bin` 直接读取回收站，都因权限/未挂载点问题失败：
```
C:\$Recycle.Bin → Recycle Bin not accessible
Shell.Application → 命令挂起
```

**结论**：恢复无望，被删目录需手动重建（如果是临时的就跳过）。
