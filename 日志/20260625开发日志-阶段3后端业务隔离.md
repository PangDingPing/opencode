# 阶段 3：后端业务隔离 + 文件路径隔离

## 需求背景

多用户系统改造阶段 3。目标：实现 session 按用户隔离（普通用户只看自己的 session，admin 看全部），session 创建时自动写入 user_id 并按实名设工作目录（如 `/workspace/上官兵/`），新增 credential.create 端点（admin-only）。

## 备选方案

1. **session.create 的 user_id 写入方式**
   - 方案 A：在 handler 层面，create 之后用 Database.Service 直接 update SessionTable
   - 方案 B（采用）：在 SessionV2.Service.create 里加 userID 参数，publish Created 事件后 update SessionTable.user_id。更内聚，user_id 写入逻辑在 service 层

2. **实名工作目录的创建时机**
   - 方案 A：在 session.create service 层面创建目录
   - 方案 B（采用）：在 handler 层面用 `mkdir(recursive: true)` 确保目录存在，再传给 service。service 层不负责目录创建

3. **UserID 类型导入**
   - user/sql.ts 原来导出 `ID`，但 session/sql.ts 和 credential/sql.ts 用 `import type { UserID }`
   - 方案 A：加 type alias `export type UserID = ID`
   - 方案 B（采用）：直接把 `ID` 重命名为 `UserID`（const + type），让 schema 和 type 都能用 `UserID` 导入

## 影响范围

- **session 隔离**：普通用户只能列出和创建自己的 session；admin 能看全部
- **工作目录隔离**：每个用户的 session 工作目录为 `{cwd}/{username}/`（如 `D:\AI\opencode\上官兵\`）
- **credential 创建**：新增 POST `/api/credential` 端点，仅 admin 可用，写入时记录 user_id
- **向后兼容**：CLI 模式（Basic Auth）注入 admin 用户，不受影响；无认证模式（开发环境）注入默认 admin，不受影响

## 踩坑记录

1. **`Credential.Stored` 类型在 server 包 typecheck 报错**
   - 现象：`groups/credential.ts(15,32): Type 'typeof Stored' is not assignable to type 'Top'`
   - 原因：core 包预存的 `Cannot find module 'effect'` 错误导致 `Schema.Class` 类型无法正确解析，`Credential.Stored` 的类型退化为 `typeof Stored`
   - 验证：用 `git stash` 对比，改动前 2897 行错误，改动后 2907 行（仅多 10 行，都是 Credential.Stored 连锁错误）
   - 结论：非逻辑错误，实际构建环境（effect 模块正常解析）不会出现

2. **UserID 导入不一致**
   - 现象：`session/sql.ts` 和 `credential/sql.ts` 用 `import type { UserID } from "../user/sql"`，但 user/sql.ts 导出的是 `ID`
   - 修复：把 user/sql.ts 的 `ID` 重命名为 `UserID`
