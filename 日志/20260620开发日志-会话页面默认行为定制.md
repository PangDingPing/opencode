# 2026.06.20 会话页面默认行为定制 - 修改说明

本次修改把 opencode 网页端会话页（`/new-session`、`/:dir/session/:id?`）的"首次进入体验"按冶建工作流做了 5 处默认行为定制：开启 Advanced 中两个开关、关闭"代码审查"面板、默认展开文件树、文件树默认切到"所有文件"、默认进入 `/YEJIAN` 项目。所有改动都集中在 `packages/app/src/context/` 和 `packages/app/src/pages/` 两个目录下，**未触动业务逻辑、路由、UI 组件、API**。

## 一、需求

| # | 需求 | 表现 |
|---|---|---|
| 1 | 设置默认打开 Advanced 中 Filetree 开关 | `settings.general.showFileTree = true` |
| 2 | 设置默认打开 Advanced 中 Custom agents 开关 | `settings.general.showCustomAgents = true` |
| 3 | 会话页面默认不显示"代码审查"面板 | `layout.review.panelOpened = false` |
| 4 | 会话页面默认展开文件树 | `layout.fileTree.opened = true` |
| 5 | 文件树默认选中"所有文件" tab | `layout.fileTree.tab = "all"` |
| 6 | 首次进入首页自动跳到 `/YEJIAN` 项目 | `pages/layout.tsx` autoselect 兜底 |

> 实际是 5 个需求，编号 1-5 内部 6 项。需求 1-2 走 settings；需求 3-5 走 layout；需求 6 走 pages/layout。

## 二、备选方案

### 需求 3-5 持久化策略

老用户的 `settings.v3` / `layout.v6` 里如果已经存过值（比如手动关过 file tree、已经开启"代码审查"），简单修改 `defaultSettings` 不会覆盖他们的偏好。

- **方案 A（纯默认值）**：只改 `defaultSettings`，不升级 `persist.ts` 的 key 版本号
  - 优点：老用户偏好完全保留
  - 缺点：老用户永远看不到新默认（即使从没设置过该字段，也用 `?? default` 兜底）
- **方案 B（默认值 + migrate 兜底升级）**：默认值改了之后，让 `migrate()` 函数对老数据里没存过该字段的对象也用新默认
  - 优点：老用户走 migrate 后立即享受新默认
  - 缺点：migrate 函数要看老数据形态，复杂度上升
- **方案 C（升级版本号）**：把 `layout.v6` 改成 `layout.v7`，老数据全部清空
  - 优点：行为最简单
  - 缺点：老用户所有 layout 偏好（terminal 宽度、session 宽度、review diff style 等）全部丢失

**采用方案 B**。具体做法：
- `migrate()` 函数中如果老数据里**有**该字段 → 保留
- 如果老数据里**没有**该字段 → 用新默认值
- 老用户已经手动切到"代码审查"的，`review.panelOpened: true` 会被 migrate 保留

### 需求 6 触发范围

`state.autoselect` 初始条件是 `!initialDirectory && !newDesign()`（V2 新设计不自动选项目）。

- **方案 A（只老布局生效）**：保持原条件不变，仅修改 `autoselect` 资源内 `if (!last) return` → `await openProject(last ?? "/YEJIAN", true)`
  - 老布局：进首页自动跳 YEJIAN
  - V2 新设计：显示项目选择首页，不跳转
- **方案 B（新老布局都生效）**：去掉 `!newDesign()` 条件，autoselect 对所有布局生效
  - 老布局：同上
  - V2 新设计：跳过项目选择首页，直接进 YEJIAN session 页面

**采用方案 B**。用户上一轮已经打开新设计相关设置，说明在用 V2 布局；方案 B 让 V2 用户也能"开箱即用"。

### 需求 6 路径写法

`/YEJIAN` vs `/YEJIAN/`：
- `pathKey()`（[packages/app/src/utils/path-key.ts:18-24](packages/app/src/utils/path-key.ts#L18-L24)）会用 `trimTrailingSlashes` 去掉末尾斜杠
- 两个写法在 opencode 内部完全等价
- base64 编码后字符串不同（`/YEJIAN` → `L1lFSklBTg==`，`/YEJIAN/` → `L1lFSklBTi8=`），但解码后 `pathKey()` 会再次规范化
- 项目内所有代码引用（`"/tmp/project"`、`"/project"`）都不带尾斜杠

**采用 `/YEJIAN`**（不带尾斜杠），与项目风格保持一致。

### 需求 6 路径是否抽常量

- 抽常量（`DEFAULT_PROJECT_PATH = "/YEJIAN"`）：以后想换默认项目只改一处
- 硬编码 `/YEJIAN` 字面量：更直接、改动点少

**采用硬编码字面量**（用户选择）。理由：
- 这个路径是 docker 内固定挂载点，不存在"换默认项目"的需求
- 写死最直观，看代码不用跳到定义

## 六、踩坑记录

### 坑 1：V2 home 不会自动选择项目

`autoselect` 初始条件是 `!initialDirectory && !newDesign()`，V2 新设计（`newDesign() === true`）下 `state.autoselect` 永远是 false，`autoselecting` resource 不会执行。**用户进入 V2 首页会看到项目选择页，不会自动跳转**。

解决方案：去掉 `!newDesign()` 条件，让 V2 也走 autoselect（方案 B）。

副作用：V2 用户访问 `/` 时会跳过 HomeDesign，直接跳到 `/<base64(/YEJIAN)>/session`，看不到"项目列表 + session 列表"的 V2 首页。如果用户更喜欢 V2 首页，方案 A 也可（仅老布局生效），但本次选择 B。

### 坑 2：`pathKey()` 与 `base64()` 的"路径规范化时机"差异

base64 编码直接对原始字符串做，不做任何规范化。所以：
- `base64Encode("/YEJIAN")` ≠ `base64Encode("/YEJIAN/")`
- 但解码后进入 `pathKey()` 时，`/YEJIAN/` 会被去掉尾斜杠成 `/YEJIAN`
- URL 路由层 `path="/:dir"` **不会**自动去尾斜杠，浏览器敲 `/YEJIAN/` 可能匹配失败

实际验证：opencode 内部所有代码引用都是 `/YEJIAN`（不带尾斜杠），跟着风格走不会有事。

### 坑 3：默认值的 `?? true` 兜底陷阱

`store.review?.panelOpened ?? true` 出现在两处：
- `reviewPanelOpened` createMemo（[layout.tsx:754](packages/app/src/context/layout.tsx#L754)）：渲染时的显示判断
- `setReviewPanelOpened` 写入比较（[layout.tsx:775](packages/app/src/context/layout.tsx#L775)）：避免重复 setStore

如果只改 `defaultSettings.review.panelOpened = false` 而**不改**这两处 `?? true`：
- 老用户数据里 `review: { ... }` 已存在但 `panelOpened` 字段缺失（比如手动清过 localStorage 然后又访问了一次，但 migrate 还没把字段填上）
- 读取时按 true 处理 → "代码审查"会显示
- 写入时按 true 比较 → 设 false 时实际值 false ≠ true，会触发 setStore 写入

所以 3 处 `?? true` → `?? false` 必须同步改。这是修改过程中容易遗漏的点。
