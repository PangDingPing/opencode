# 2026-06-25 前端联调：跨域 cookie 修复 + 浏览器测试

## 需求背景

阶段 4 前端完成后进行浏览器联调测试。发现 SDK 直连后端 `http://localhost:4098`（跨域 :3000 → :4098），`SameSite=Lax` cookie 不在跨域 fetch 中发送，导致 SSE `/global/event` 和所有 SDK API 请求返回 401。

## 问题分析

### 根因

1. `entry.tsx` 的 `getCurrentUrl()` 在 dev 模式返回 `http://localhost:4098`（后端直连地址）
2. SDK 用此 URL 作为 `baseUrl`，所有请求直接发到 `:4098`
3. 浏览器从 `:3000`（vite dev server）访问页面，cookie 域是 `localhost:3000`
4. `SameSite=Lax` cookie 不会在跨端口 fetch 请求中发送
5. 后端 `authorizationLayer` 收不到 cookie → 401

### 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A. SDK 走 vite proxy（同源） | 通用，dev/prod 均同源 | 需列出所有 proxy 路径 | ✅ 选用 |
| B. `SameSite=None; Secure` | 改动小 | HTTP 下 `Secure` 不生效（Docker 部署无 HTTPS） | ✗ |
| C. `SameSite=None` 无 `Secure` | 改动最小 | 现代浏览器拒绝 | ✗ |

## 文件改动

### `packages/app/src/entry.tsx`（修改，L102-106）

`getCurrentUrl()` dev 模式不再拼 `http://localhost:4098`，直接返回 `location.origin`：

```ts
// 改前
if (import.meta.env.DEV)
  return `http://${import.meta.env.VITE_OPENCODE_SERVER_HOST ?? "localhost"}:${import.meta.env.VITE_OPENCODE_SERVER_PORT ?? "4096"}`

// 改后
// dev 模式走 vite proxy（同源），prod 也是同源（前端嵌入后端），均用 location.origin
return location.origin
```

### `packages/app/vite.config.ts`（修改，L28-42）

proxy 从 4 条规则扩展到 25 条，覆盖 SDK 所有顶层路径前缀：

```ts
proxy: (() => {
  const backend = "http://127.0.0.1:4098"
  const paths = [
    "/api", "/global", "/event", "/config", "/session", "/file", "/find",
    "/path", "/vcs", "/command", "/lsp", "/formatter", "/mcp", "/project",
    "/question", "/permission", "/provider", "/instance", "/agent",
    "/skill", "/log", "/auth", "/experimental", "/doc",
  ]
  const entries = Object.fromEntries(paths.map((p) => [p, backend]))
  entries["/pty"] = { target: backend, ws: true }
  return entries
})(),
```

路径列表来源：`packages/sdk/js/src/v2/gen/sdk.gen.ts` 中所有 `url: "/..."` 的顶层前缀。directory 通过 query 参数传递（非 URL 路径），不影响 proxy 规则。

## 影响范围

- **dev 模式**：前端所有 SDK 请求走 `http://localhost:3000/...` → vite proxy → `http://127.0.0.1:4098/...`，同源，cookie 正常发送
- **prod 模式**：前端嵌入后端二进制，本身同源，不受影响
- `VITE_OPENCODE_SERVER_PORT` 环境变量不再需要设置（`getCurrentUrl` 不再引用它）

## 踩坑记录

### 1. SSE 401 错误在登录前出现

`GlobalProvider` 在 AuthGate 之外初始化 SDK context，SDK `onMount` 立即启动 SSE 连接。未登录时 SSE 返回 401 是**预期行为**，不影响登录页渲染。登录后 cookie 设置，SDK 自动重连（250ms 间隔）。

### 2. PowerShell curl JSON 转义

PowerShell 下 `curl` 是 `Invoke-WebRequest` 别名，`-d '{"key":"value"}'` 的引号会被 PowerShell 解析导致 JSON 格式错误。解决：用 `curl.exe` + `-d @file.json` 从文件读取 body。

### 3. 临时文件清理

删除了 16 个测试临时文件（`reset-user.ts`, `reset-admin.ts`, `check-users.ts`, `serve-test.js`, `cookie-*.txt`, `login*.json`, `chpwd*.json`）和 33 个测试日志文件（`测试-后端启动*.log`, `测试-import*.log` 等）。

```bash
# 5. SSE /global/event（带 cookie）
curl.exe -s -i -N http://localhost:3000/global/event -b cookie-dev.txt --max-time 3
# → 200 OK + text/event-stream + server.connected 事件 ✅
```
