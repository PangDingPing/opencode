## 踩坑记录

**Edit 工具重写 .ps1 丢 UTF-8 BOM → Windows PowerShell 5.1 按 GBK 误读 → 中文注释吞换行符 → 语法错误**：

1. 现象：`build.ps1` 报 `The Try statement is missing its Catch or Finally block`，**报错行号 119 与实际文件 125 不符**（偏移 6 行）
2. 根因链：原 build.ps1 带 UTF-8 BOM（PS 5.1 靠 BOM 识别 UTF-8）→ Edit 工具重写文件时 **BOM 丢失** → PS 5.1 退化按 ANSI/GBK 解码 → 中文注释最后一个字节与 `\n` 组成非法 GBK 字节对 → **换行符被吞** → 下一行 `if ($EnvFile...)` 被并进注释失效 → try 块结构破坏
3. 诊断技巧：`[System.Text.Encoding]::GetEncoding(936).GetString(bytes)` 模拟 PS 5.1 视角读文件，直接看到吞行现场；`git cat-file -p docker-v0.1.5:docker/build.ps1` 对比确认原文件带 BOM（首字节 239 187 191）
4. 修复：`[System.IO.File]::WriteAllText($path, $content, [System.UTF8Encoding]::new($true))` 补回 BOM + 我新增的中文注释改英文；`Parser::ParseFile` 验证 PARSE OK
5. **教训：今后编辑 .ps1/.cmd 等 PS/ cmd 生态文件后，必须验证 BOM 是否保留**；中文注释行号偏移是 GBK 误读的典型指纹

**npm 全局包验证要用 `/usr/local/lib/node_modules`**：Alpine 的 npm prefix 是 /usr/local（不是 Debian 系的 /usr/lib），且 node 默认不解析全局包路径，容器内验证要 `NODE_PATH=/usr/local/lib/node_modules node -e "require('...')"`。用 `require('pkg/package.json')` 查版本会被 exports 字段挡（ERR_PACKAGE_PATH_NOT_EXPORTED），直接 require 主模块即可。
