# 2026.06.15 网页端系统通知图标本地化 - 修改说明

本次修改将 opencode 网页端"系统通知"（任务完成 / 错误 / 权限询问）图标从写死的 CDN 地址改为本地静态资源，与 6-14 已完成的浏览器标签 / Favicon / 字标品牌化保持一致。

## 二、修改文件清单

### 1. 系统通知图标本地化

**文件**：`packages/app/src/entry.tsx`

**问题**：第 72 行 `notify` 函数构造 `new Notification(title, { icon: ... })` 时，icon 写死为 `https://opencode.ai/favicon-96x96-v3.png`（走远程 CDN）。在断网 / 访问慢 / opencode.ai 不可达时会拉取失败，且图标风格与本项目"广东冶建图审AI工作台"品牌完全不一致。

**修改内容**：把硬编码的 CDN URL 替换为 Vite 静态资源根路径下的本地图标（`packages/app/public/LOGO1.ico`，6-14 步骤三已经放进 public/）。

**修改前后对比**（仅第 72 行一处）：

```ts
  const notification = new Notification(title, {
    body: description ?? "",
-   icon: "https://opencode.ai/favicon-96x96-v3.png",
+   icon: "/LOGO1.ico",
  })
```

**为什么这样改**：

- `packages/app/public/` 下的文件会被 Vite 在 dev 模式和构建产物中以根路径直接暴露
- `/LOGO1.ico` 在 6-14 已经作为浏览器标签 / apple-touch-icon / shortcut icon 多处引用，可直接复用
- 不需要新增任何资源文件，零额外网络请求，离线也能正常弹通知

## 五、启动验证

修改完成后分别启动前后端进行验证。

### 5.1 后端

```
cd packages\opencode
bun run --conditions=browser ./src/index.ts serve --port 4096
```

**问题排查**：第一次启动遇到 `Error: Unexpected error` + `ServeError`，被 PowerShell 错误信息包装吞掉真实原因。写临时脚本 `dump-err.mjs` 用 `process.on("uncaughtException")` 抓取后得到 `cause: { code: "EADDRINUSE" }` —— 4096 端口已被未知进程占用。

**解决**：把 `--port 4096` 改成 `--port 5099`（或 `0` 让系统自动选）后启动正常，输出：

```
opencode server listening on http://127.0.0.1:5099
```

> 临时调试脚本 `dump-err.mjs` 已在排查完成后删除，不入库。

### 5.2 前端

```
cd packages\app
bun dev -- --port 4444
```

### 5.3 浏览器验证

1. 浏览器访问 `http://localhost:4444`，进入 `/new-session` 或 `/:dir/session/...` 任一会话页面
2. 触发一个会弹系统通知的事件（例如在 Web 端跑一个会完成的后台任务）
3. 在浏览器**最小化 / 切到其他标签**的状态下等通知弹出
4. 操作系统通知卡片左上角图标应显示为 **广东冶建 LOGO**（即 `LOGO1.ico`），不再是 opencode 默认图标
5. DevTools → Network 面板：不应再有 `opencode.ai/favicon-96x96-v3.png` 的请求
