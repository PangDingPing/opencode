# 登录改密与账号设置 UI 调整

## 需求背景

用户反馈三个问题：

1. **改密跳转 BUG**：用户首次登录修改密码后跳转 `http://localhost:3000/login` 无反应，应该直接跳转新建会话页。
2. **删除账号按钮**：账号设置页面需要取消"删除账号"按钮。
3. **LOGO 与标题**：
   - 登录页 LOGO 修改为 `packages/app/public/LOGO.png`
   - 登录页"请登录后使用"上方的"opencode"修改为"冶建图审·数智办公系统"
   - 首次登录改密页 LOGO 也修改为 `LOGO.png`

## 备选方案

### 改密跳转目标

- 方案 A：跳转到 `/new-session`（路由表中已有的新建会话路由）✅ 采用
- 方案 B：跳转到 `/`（首页路由，会进入默认会话视图）
- 方案 C：用 `window.location.reload()` 让 AuthGate 重新挂载（参考日常改密弹窗 `change-password-dialog.tsx` 的做法）

选 A 的理由：用户明确要求"直接跳转新建会话"，`/new-session` 是路由表中已存在的路径（`app.tsx:419`），语义最贴合。

### 修改密码按钮（设置页）

设置页"修改密码"按钮原本跳 `/change-password`，但路由表无此路径，会匹配到 `/:dir` 路由把 `change-password` 当成目录名查询会话，触发后端 `Path is not absolute` 错误。

- 方案 A：弹窗方式（复用 `ChangePasswordDialog` 组件，与顶栏用户菜单一致）✅ 采用
- 方案 B：新增 `/change-password` 路由
- 方案 C：保留页面跳转但改为合法路由

选 A 的理由：与 `user-menu.tsx` 顶栏菜单的现有行为保持一致，无需新增路由，最小改动。

## 踩坑记录

### 坑 1：改密跳转 `/login` 导致页面无反应

**现象**：首次登录改密成功后页面跳到 `/login` 但显示空白。

**根因**：路由表（`app.tsx` 第 418-425 行）中根本没有 `/login` 路由。整个登录、改密流程由 `AuthGate`（`auth.tsx`）统一控制，**不通过路由切换**：
- 未登录 → 渲染 `LoginPage`
- 已登录但 `must_change_password=true` → 渲染 `ChangePasswordPage forceMode`
- 已登录且密码正常 → 渲染子组件

`/login` 没有匹配的路由，浏览器跳转后 AuthGate 重新挂载，由于用户已登录且改密后 `must_change_password` 已为 false，AuthGate 渲染子组件，但 URL 是 `/login` 没匹配到任何路由，所以页面看起来"无反应"。

**解决**：改为跳转 `/new-session`（路由表中已定义）。

### 坑 2：设置页"修改密码"按钮触发后端 `Path is not absolute` 错误

**现象**：在 `/settings` 页点"修改密码"按钮，前端报"无法加载 ****的会话 Unexpected server error"，后端报：

```
error: Path is not absolute: r���j�0��
  at absolute (D:\AI\opencode\packages\core\src\database\path.ts:17:15)
  ...
  at listByProject (D:\AI\opencode\packages\opencode\src\session\session.ts:1061:6)
```

**根因**：设置页"修改密码"按钮 `onClick={() => (window.location.href = "/change-password")}`，但路由表里没有 `/change-password` 路由。SolidJS Router 把它匹配到了 `/:dir` 路由（`app.tsx:420`），把 `change-password` 当成目录名，再去后端 `listByProject` 查这个"目录"的会话列表，触发 `Path is not absolute` 错误（因为 `change-password` 不是合法的存储路径）。

**解决**：参照 `user-menu.tsx:19-21` 顶栏菜单的写法，改成弹出 `ChangePasswordDialog` 对话框，不再做页面跳转。

### 坑 3：原 `settings.tsx` 使用了未导入的 `Show`

**现象**：原 `settings.tsx` L63-65 使用了 `<Show when={error()}>`，但 import 中只有 `createSignal, type Component`，没有 `Show`。属预先存在的代码缺陷。

**解决**：本次完全重写 settings.tsx 时一并清理（移除了 error 信号和 Show 块）。

### 坑 4：LOGO 尺寸控制

**问题**：原 `<Splash class="w-12 h-15" />` 是竖向比例 SVG（48x60）。`LOGO.png` 是横向 logo，若直接套用 `w-12 h-15` 会被强行拉伸为竖向比例变形。

**解决**：改为 `class="h-15 w-auto"`（高 60px、宽度按图片原始比例自适应），保持 LOGO 原始宽高比。
