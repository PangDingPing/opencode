# 阶段 2：后端认证（双认证模式 + 用户服务 + 令牌服务）

## 需求背景

多用户系统改造阶段 2。目标：实现后端认证逻辑，包括用户服务（创建/验证/查询/改密）、认证令牌服务（创建/验证/续期/撤销）、双认证中间件（cookie token for web + Basic Auth for CLI）、5 个认证端点（login/logout/me/change-password/allowed-names）、首次启动管理员引导。

## 备选方案

1. **认证模式设计**
   - 方案 A：只用 cookie token
   - 方案 B（采用）：双认证模式。Web 端用 cookie token（7 天 TTL + 惰性续期），CLI 端保留 Basic Auth（向后兼容）。两种模式都注入 CurrentUser 到 Effect Context

2. **令牌续期策略**
   - 方案 A：每次请求都 UPDATE last_extend_at
   - 方案 B（采用）：惰性续期，5 分钟内不重复 UPDATE。减少数据库写入压力

3. **CurrentUser 注入方式**
   - 方案 A：通过函数参数传递
   - 方案 B（采用）：通过 Effect Context.Service 注入（`Context.Tag("@opencode/CurrentUser")`）。业务 handler 用 `yield* CurrentUser` 获取，解耦认证与业务

4. **首次启动管理员引导**
   - 方案 A：migration 创建固定管理员
   - 方案 B（采用）：serve.ts 启动时检查 user 表，空则创建 admin 用户，密码从 `OPENCODE_ADMIN_PASSWORD` 环境变量读取，未设则 fail-fast

5. **登录限速**
   - 方案 A：数据库记录失败次数
   - 方案 B（采用）：内存计数，同 IP 5 次失败锁 15 分钟。简单高效，重启后清零（可接受）

## 文件改动

### 1. 新建 `packages/core/src/user/index.ts`
- `User.Service`（Context.Service）：
  - `createUser(input)` — 创建用户（校验白名单，argon2id 哈希密码）
  - `verifyPassword(username, password)` — 验证密码
  - `getUser(userID)` — 获取用户信息
  - `listUsers()` — 列出所有用户
  - `changePassword(userID, oldPassword, newPassword)` — 改密（验证旧密码，踢出其他设备）
  - `resetPassword(userID, newPassword)` — 重置密码（admin 用，设 must_change_password=1）
  - `setDisabled(userID, disabled)` — 禁用/启用
  - `getAllowedNames()` — 获取白名单
- `validatePassword(pwd)` — 密码强度校验：8位+含字母+含数字
- `UserInfo` 类型：id, username, role, display_name, disabled, must_change_password
- admin 不受白名单限制

### 2. 新建 `packages/core/src/auth-token/index.ts`
- `AuthToken.Service`（Context.Service）：
  - `create(userID, meta)` — 创建令牌（32 字节随机，base64url，7 天 TTL）
  - `verify(token)` — 验证令牌（检查过期和撤销）
  - `extend(token)` — 惰性续期（5 分钟内不重复 UPDATE）
  - `revoke(token)` — 撤销单个令牌
  - `revokeAllForUser(userID)` — 撤销用户所有令牌（改密踢人用）
  - `cleanupExpired()` — 清理过期令牌

### 3. 新建 `packages/server/src/middleware/auth.ts`
- `SESSION_COOKIE = "oc_session"` — cookie 名称常量
- `CurrentUser` Tag — `Context.Tag("@opencode/CurrentUser")<CurrentUser, UserInfo>()`
- `CookieAuth` 中间件骨架（实际 cookie 解析逻辑在 authorization.ts 内联）
- `parseCookie(header)` — 解析 cookie 头

### 4. 新建 `packages/server/src/middleware/authorization.ts`
- 双认证模式中间件：
  1. **Cookie token（Web 端）**：从 cookie 取 `oc_session` → verify → 惰性续期 → 加载用户 → 检查 disabled → 注入 CurrentUser
  2. **Basic Auth（CLI 端）**：从 Authorization 头取 Basic 凭据 → verifyPassword → 创建临时 token → 注入 CurrentUser
  3. **无认证模式（开发环境）**：前两种都失败时，注入默认 admin 用户（仅当 OPENCODE_SERVER_PASSWORD 未设）
- 公开路径：`/api/auth/login`, `/api/health` 不走认证
- cookie 存在但无效 → 拒绝（返回 401 "登录已过期"）

### 5. 新建 `packages/server/src/middleware/require-admin.ts`
- `RequireAdmin` 中间件：检查 `CurrentUser.role === "admin"`，否则返回 ForbiddenError (403)
- `requireAdminLayer` — 提供 RequireAdmin 中间件的 Layer

### 6. 新建 `packages/server/src/handlers/auth.ts`
- 5 个端点 handler：
  - `auth.login` — 登录（限速检查、白名单校验、密码验证、创建 token、设置 cookie）
  - `auth.logout` — 登出（撤销当前 token、清除 cookie）
  - `auth.me` — 获取当前用户信息
  - `auth.change-password` — 改密（验证旧密码、设新密码、revokeAllForUser 踢出其他设备）
  - `auth.allowed-names` — 获取白名单
- 登录限速：内存 Map 记录 IP 失败次数，5 次失败锁 15 分钟
- 辅助函数：`parseCookie`, `setSessionCookie`, `clearSessionCookie`

### 7. 新建 `packages/server/src/groups/auth.ts`
- `AuthGroup` 定义 5 个端点：
  - `POST /api/auth/login` — payload: `{ username, password }`
  - `POST /api/auth/logout` — 无 payload
  - `GET /api/auth/me` — 返回 CurrentUser 信息
  - `POST /api/auth/change-password` — payload: `{ oldPassword, newPassword }`
  - `GET /api/auth/allowed-names` — 返回 `{ names: string[] }`

### 8. 修改 `packages/opencode/src/cli/cmd/serve.ts`
- 新增 `bootstrapAdmin` 逻辑：
  - 启动时检查 user 表是否为空
  - 空则创建 admin 用户，密码从 `OPENCODE_ADMIN_PASSWORD` 环境变量读取
  - 未设密码则 fail-fast（拒绝启动，提示设置环境变量）

### 9. 修改 `packages/server/src/errors.ts`
- 新增 `ForbiddenError`（403）— 用于 RequireAdmin 中间件

### 10. 修改 `packages/server/src/api.ts`
- 注册 `AuthGroup` 到 Api

### 11. 修改 `packages/server/src/handlers.ts`
- 注册 `AuthHandler`
- 提供 `User.defaultLayer` 和 `AuthToken.defaultLayer`

### 12. 修改 `packages/server/src/routes.ts`
- 提供 `User.defaultLayer` 和 `AuthToken.defaultLayer`

## 影响范围

- **认证流程**：Web 端登录后获得 cookie token，后续请求自动认证；CLI 端用 Basic Auth，向后兼容
- **权限基础**：CurrentUser 注入为阶段 3 的业务隔离和阶段 4 的前端权限控制提供基础
- **首次启动**：管理员必须设置 `OPENCODE_ADMIN_PASSWORD` 环境变量才能启动服务
- **登录安全**：登录限速防止暴力破解，改密踢出其他设备防止会话劫持
- **向后兼容**：CLI 模式和无认证开发模式不受影响

## 踩坑记录

1. **`import { User, type User.UserInfo }` 语法错误**
   - 现象：TypeScript 不支持这种混用导入
   - 修复：分开导入 `import { User } from "..."` + `import type { UserInfo } from "..."`
   - 并修改 CurrentUser Tag 定义从 `User.UserInfo` 改为 `UserInfo`

2. **server 包 typecheck 大量 "Cannot find module" 错误**
   - 现象：2924 个错误
   - 排查：通过 `git stash` 对比确认是预存问题（tsgo 配置问题），不是本次改动引入

3. **PowerShell 不支持 `&&` 和 heredoc**
   - 现象：git commit 命令失败
   - 解决：改用 `;` 分隔和多个 `-m` 参数
