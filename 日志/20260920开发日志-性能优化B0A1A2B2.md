## 备选方案

- **A2 按时间删**：event 表加 `created_at` 列并回填 vs 从 ID 解码时间戳。选后者——加列需改上游 schema + 迁移 + 写路径（commitSyncEvent 事务），改动面大；ID 本身含时间戳，读侧解码零侵入。
- **A1 迁移方式**：`docker cp` vs 临时容器 `cp -a`。选临时容器（volume 挂载后容器内 `cp -a` 保权限/属主，且 WAL checkpoint 先做保证主库文件完整）。
- **B0 抖动**：固定比例 0~25% vs 全随机。选固定比例，实现一行且足以切断同步重连。

### A2：`docker/cleanup-events.py`（新建 130 行）

- 参数：`--days 30`（默认）、`--dry-run`、`--vacuum`；DB 默认 `/root/.local/share/opencode/opencode.db`；`PRAGMA busy_timeout = 5000`
- 核心难点：**事件 ID 时间位 48bit 回绕，不能 SQL 比较**（见踩坑 2）。Python 侧逐条解码：

```python
WRAP_MS = 1 << 48  # ID 时间位 48 bit 回绕周期（约 792 天）
DATE_WINDOW_MS = 790 * 86400 * 1000  # 可定日期窗口
SLACK_MS = 2 * 86400 * 1000

def decode_event_ts(eid, k_now, now_ms):
    try:
        prefix = int(eid[4:16], 16)
    except ValueError:
        return None
    for k in (k_now, k_now - 1):
        cand = (prefix + k * WRAP_MS) >> 12
        if now_ms - DATE_WINDOW_MS <= cand <= now_ms + SLACK_MS:
            return cand
    return None
```

- 主流程：解码筛出过期 ID → `executemany DELETE FROM event` → `DELETE FROM event_sequence WHERE aggregate_id NOT IN (SELECT DISTINCT aggregate_id FROM event)` → commit → `PRAGMA wal_checkpoint(TRUNCATE)`

## 踩坑记录

1. **E:/D: 环境错配（差点迁错库）**：仓库 `docker/run.ps1` 写的是 D: 路径，最初按它做迁移准备；实际检查发现生产容器挂的是 E:——E: 库 301MB 当天还在写（是现行数据），D: 只有 278KB 停在 8/30（旧废弃目录）。**教训：动手改生产前必须先核对实际运行环境（docker inspect 看真实挂载），不能信仓库脚本。** 同时发现上一轮报告 v1.2 自己把三处证据路径 E:→D: 改错了，本次一并修正并加勘误标注。
2. **事件 ID 48bit 时间位回绕**：A2 最初想用 `(ts_ms << 12).to_bytes(6, "big")` 生成边界 ID 做 SQL 范围比较，直接 OverflowError。深挖 `packages/core/src/util/identifier.ts` 发现 `Buffer.alloc(6)` 编码时**只保留时间戳低 48 位**（高位截断），约 792 天回绕一次，当前回绕边界 2026-08-14 11:19:55。实证确认线上数据恰好跨边界：8/6 的 max ID `0xfd79...` 在时间上**早于** 8/15 的 min ID `0x003a...`——回绕点两侧 ID 字典序 ≠ 时间序，SQL 按 ID 排序/比较时间全是错的。**教训：opencode 的 ID 不能当时间有序键用；任何按 ID 范围过滤时间的逻辑都必须考虑回绕。** 脚本改为 Python 侧逐条解码（k 候选法：对每个 ID 尝试当前/上一个回绕周期，落在 790 天可定日期窗口内才采信）。
3. **临时容器跑命令被 ENTRYPOINT 吞掉**：镜像 ENTRYPOINT 是 `opencode web`，`docker run --rm ... python3 -c "..."` 实际执行的是 opencode web 的帮助输出。必须加 `--entrypoint python3`（或 `sh`）覆盖。
4. **PowerShell 5.1 不支持 `&&`**：链式命令报 `The token '&&' is not a valid statement separator`，改用 `;`。
5. **git 提交需关沙箱**：沙箱内 git 写 `.git/objects` 报 Permission denied，提交命令需 `dangerouslyDisableSandbox`。
