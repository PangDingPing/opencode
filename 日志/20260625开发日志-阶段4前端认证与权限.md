# 阶段 4：前端登录页 + AuthGate + 普通用户隐藏 provider 设置 + 用户管理页

## 需求背景

多用户系统改造阶段 4。目标：实现前端登录认证流程，包括登录页、AuthGate 包裹、首次登录强制改密、普通用户隐藏 provider 设置、用户菜单（退出登录/修改密码/用户管理入口）。

## 备选方案

1. **AuthGate 的位置**
   - 方案 A：在最外层（ServerProvider 之外）包裹
   - 方案 B（采用）：在 ConnectionGate 之后、Router 之前包裹。这样只有连接成功且登录后才进入应用，且 AuthGate 能访问 ServerProvider 提供的上下文

2. **登录页/改密页的加载方式**
   - 方案 A：静态导入
   - 方案 B（采用）：用 lazy 动态导入，避免首屏加载过多代码。登录页和改密页只在未登录或首次登录时才需要

3. **用户菜单的组件结构**
   - 方案 A：直接在 titlebar.tsx 里内联
   - 方案 B（采用）：新建独立的 UserMenu 组件，在 titlebar 的 legacy 和 v2 右侧区域都引用。降低 titlebar 的复杂度

4. **i18n 文案处理**
   - 方案 A：在 zh.ts 和 en.ts 都加新 key
   - 方案 B（采用）：登录页/改密页/用户菜单的文案直接用中文硬编码。因为这些页面只有中文用户使用，且 i18n 的 Keys 类型限制需要同步更新 en.ts，增加维护成本

## 文件改动

### 1. 新建 `packages/app/src/context/auth.tsx`（82 行）
- 定义 `CurrentUser` 类型：id, username, role, display_name, must_change_password
- `UserContext`：SolidJS createContext
- `useCurrentUser()`：获取当前用户（必须在 AuthGate 内使用），返回 `{ user, isAdmin }`
- `useCurrentUserOptional()`：可选获取（未登录时返回 undefined）
- `fetchMe()`：从 `/api/auth/me` 获取当前用户信息
- `AuthGate`：核心组件
  - 加载中 → 显示 Splash 动画
  - 未登录 → 显示 LoginPage
  - 已登录但 must_change_password → 显示 ChangePasswordPage（forceMode）
  - 已登录且不需要改密 → 渲染子组件，注入 UserContext
- `logout()`：调用 `/api/auth/logout` 后刷新页面

### 2. 新建 `packages/app/src/pages/login.tsx`（100 行）
- 用户名 + 密码表单
- 提交时 POST `/api/auth/login`
- 登录成功回调 `onLoginSuccess()`（触发 AuthGate refetch）
- 错误处理：显示后端返回的错误消息（包括登录限速锁定提示）

### 3. 新建 `packages/app/src/pages/change-password.tsx`（140 行）
- 两种模式：
  - `forceMode=true`（首次登录）：只输入新密码 + 确认密码，不要求旧密码
  - `forceMode=false`（日常改密）：旧密码 + 新密码 + 确认密码
- 密码强度校验：8位+含字母+含数字（前端校验，与后端一致）
- 提交时 POST `/api/auth/change-password`
- 改密成功后 `window.location.reload()` 让 AuthGate 重新获取用户状态

### 4. 修改 `packages/app/src/app.tsx`
- 新增 `import { AuthGate } from "@/context/auth"`
- 在 `ConnectionGate` 内部、`Dynamic component={props.router ?? Router}` 外部包裹 `<AuthGate>`

### 5. 修改 `packages/app/src/components/settings-v2/dialog-settings-v2.tsx`
- 新增 `import { Show } from "solid-js"` 和 `import { useCurrentUser } from "@/context/auth"`
- 获取 `const { isAdmin } = useCurrentUser()`
- 用 `<Show when={isAdmin()}>` 包裹 server 相关的 tab（servers/providers/models）的 Trigger 和 Content
- 普通用户只能看到 general 和 shortcuts 两个 tab

### 6. 新建 `packages/app/src/pages/admin/users.tsx`（72 行）
- admin-only 用户管理页
- 从 `/api/auth/allowed-names` 获取白名单列表
- 显示白名单表格（序号、实名、状态）
- 完整的用户管理功能（重置密码、禁用、踢人）预留到阶段 5 后端 API 完善后

### 7. 新建 `packages/app/src/components/user-menu.tsx`（74 行）
- 顶栏用户菜单组件
- DropdownMenu 触发按钮（user 图标）
- 显示当前用户实名 + 角色（管理员/普通用户）
- 菜单项：修改密码（弹出 ChangePasswordDialog）、用户管理（admin 可见，新窗口打开）、退出登录
- 退出登录调用 `logout()` 函数

### 8. 新建 `packages/app/src/components/change-password-dialog.tsx`（130 行）
- 日常改密对话框（在 dialog 里弹出，非整页）
- 旧密码 + 新密码 + 确认密码表单
- 密码强度校验
- 改密成功后关闭对话框并刷新页面

### 9. 修改 `packages/app/src/components/titlebar.tsx`
- 新增 `import { UserMenu } from "./user-menu"`
- 在 legacy titlebar 右侧区域（`#opencode-titlebar-right` 之后）加 `<UserMenu />`
- 在 v2 titlebar 的 `TitlebarV2Right` 函数里（`#opencode-titlebar-right` 之后）加 `<UserMenu />`

## 影响范围

- **认证流程**：未登录用户被重定向到登录页，登录后才能使用应用
- **首次登录强制改密**：must_change_password=true 的用户必须改密后才能使用
- **权限隔离**：普通用户在设置对话框看不到 servers/providers/models 三个 tab
- **用户菜单**：所有用户可通过顶栏用户菜单退出登录、修改密码；admin 额外看到用户管理入口
- **向后兼容**：CLI 模式（Basic Auth）和无认证模式（开发环境）不受影响，AuthGate 的 /api/auth/me 会返回注入的用户
