# 源码直跑模式启动修复：Schema.Defect 回退 + 循环依赖打破 + admin 账号预置

## 需求背景

从 Docker binary 部署切换回本地源码开发模式（`bun run --conditions=browser ./src/index.ts serve`）后，连续遇到 3 个阻塞问题：

1. **`Schema.Defect is not a function`**：模块加载期报错，后端起不来
2. **`Cannot access 'node' before initialization`**：`database.ts` / `user/index.ts` TDZ 错误
3. **admin 账号 `yejian / Yejian2016` 登录报"用户名或密码错误"**：本地数据库没 yejian 用户

三个问题根因不同但都源于"binary 编译模式 vs 源码直跑模式"的差异，本日志按修复顺序记录。

## 备选方案

### 问题 1：Schema.Defect 调用方式

当前 effect 版本是 `4.0.0-beta.74`，`Schema.Defect` 是常量 schema 对象（`Union([Declaration, Unknown])`），不是函数。v0.1.6 时代为了适配而做的 `Schema.Defect → Schema.Defect()` 在当前 effect 版本下反而是错的。

- **方案 A（✅ 采用）**：回退所有 `Schema.Defect()` 为 `Schema.Defect`，与当前 effect 版本一致
- 方案 B：升级 effect 到 beta 83+（上游 commit `4f1ae1604` 已做相同修改），改动面大，否决

### 问题 2：TDZ 循环依赖

错误堆栈在 `user/index.ts:284` 的 `Database.node`。诊断 log 发现 `user/index.ts` 先于 `database.ts` 执行——存在循环依赖：

```
database.ts → migration.ts → seed_initial_users.ts
  → import { hashPassword } from "../../user"        (触发 user/index.ts 整模块加载)
  → user/index.ts: import { Database } from "../database/database"
  → 循环回 database.ts（此时 database.ts 模块体还没执行到 export const node）
  → user/index.ts 顶层 export const node = LayerNode.make(..., [Database.node])
  → Database.node 处于 TDZ → 报错
```

Docker binary 能跑是因为 Bun compile 把模块体包成 lazy 函数，绕过了 TDZ；源码直跑是标准 ESM 同步求值，暴露循环依赖。

- **方案 A（✅ 采用）**：把 `hashPassword` / `verifyPasswordHash` / `validatePassword` 拆到独立叶子模块 `user/password.ts`（不 import Database），`seed_initial_users.ts` 改 import `user/password`，打破循环
- 方案 B：把 `export * as` 移到文件第 1 行（与上游 dev 一致）—— 实测单独这样做不够，循环依赖仍在
- 方案 C：把 `export const node` 改成 lazy getter —— 治标不治本

### 问题 3：admin 账号缺失

本地数据库 `C:\Users\fun2k\.local\share\opencode\opencode-local.db` 有 32 个白名单用户，但没 yejian。原因：
- `bootstrapAdmin()` 因 user 表 count > 0 跳过
- `bootstrapUsers()` 因本地没设 `OPENCODE_SEED_USERS_FILE` 环境变量跳过

- **方案 A（✅ 采用）**：启动时设 `OPENCODE_SEED_USERS_FILE` 指向项目 `docker/seed-users.json`，`bootstrapUsers()` 自动创建 yejian（幂等）
- 方案 B：用 `docker/insert-user.py` 手动插入 —— 绕道方案，不优雅

## 踩坑记录

### 坑 1：以为把 `export * as` 移到第 1 行就能解决 TDZ

第一次修复尝试：只把 `database.ts` / `user/index.ts` / `auth-token/index.ts` 的自引用 `export * as` 从末尾移到第 1 行（与上游 dev 一致）。实测仍报 `Cannot access 'node' before initialization`。

加诊断 log 发现 `database.ts` 的 log 没打印，反而 `user/index.ts` 先执行——说明循环依赖才是根因，自引用位置只是表象。真正的修复必须打破循环依赖链。

### 坑 2：最小复现无法触发 TDZ

为了确认 `export * as` + 跨文件 import 命名空间 是否必然触发 TDZ，写了最小复现 `test-tdz-self.ts` + `test-tdz-import.ts`，结果不触发。说明 TDZ 不是自引用本身的固有特性，而是**循环依赖链 + 顶层 `export const` 求值时机**共同导致。最小复现没有循环依赖，所以不触发。

### 坑 3：不是操作系统的原因

用户疑问"是不是 PowerShell vs Linux 的差异"。实际不是——同一份代码，Docker binary 能跑、源码报错，是 **binary 编译模式 vs 源码直跑模式** 的差异：
- Docker 里跑的是 `bun build --compile` 后的 binary，模块求值是 lazy 的（首次访问导出才执行模块体），绕过 TDZ
- Windows PowerShell `bun run` 是直接跑 TS 源码，标准 ESM 同步求值，触发 TDZ

### 坑 4：admin 账号从未被创建

本地数据库有 32 个白名单用户（之前 Docker 部署时 `OPENCODE_SERVER_PASSWORD=Yejian2016` 种子迁移生成的），但没 yejian。`bootstrapAdmin()` 因 count > 0 跳过，`bootstrapUsers()` 因没设 `OPENCODE_SEED_USERS_FILE` 跳过。必须显式设环境变量才会创建。
