# 新建会话页面默认加载文件树侧边栏

## 一、问题分析

### 现状
新建会话页面（路由 `/new-session`）由 [new-session.tsx](file:///d:/AI/opencode/packages/app/src/pages/new-session.tsx) 实现，它**只渲染一个输入框**（`SessionComposerRegion`），完全不挂载文件树侧边栏。

### 根本原因（三层）

1. **`new-session.tsx` 不渲染 `SessionSidePanel` 组件**
   - 文件第 52-77 行的 JSX 只包含 `NewSessionDesignView` + `SessionComposerRegion`
   - 文件顶部注释（第 11-15 行）明确说明：draft 页"no terminal, review pane, file tree, or message timeline"

2. **没有切换入口**
   - `new-session.tsx` 不渲染 `SessionHeader`（标题栏），所以没有文件树切换按钮
   - 不使用 `useSessionCommands`，所以没有 `Ctrl+\` 快捷键

3. **`SessionSidePanel` 自身有防御性判断**
   - [session-side-panel.tsx:216](file:///d:/AI/opencode/packages/app/src/pages/session/session-side-panel.tsx#L216) 行：`<Show when={isDesktop() && !(settings.general.newLayoutDesigns() && !params.id)}>`
   - 当启用新布局且无 session id 时，整个 `<aside>` 不渲染

### 设计意图
draft 页是"轻量入口"，只放输入框让用户敲第一条 prompt。提交后才升级为真实 session，跳转到 `/:dir/session/:id`，此时才挂载完整侧边栏。

## 二、方案选择

### 方案对比

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 复用完整 SessionSidePanel | 在 new-session.tsx 渲染 SessionSidePanel，传空 review props，改防御判断 | 功能完整 | 需提供 11 个 props（全为空）、改 session-side-panel.tsx 防御判断、useSessionLayout 在无 params.dir 时行为不确定、改动大 |
| **B. 独立轻量文件树侧边栏（推荐）** | 在 new-session.tsx 直接渲染 `FileTree` 组件 + 宽度手柄，复用 `layout.fileTree` 状态 | 最小改动、独立性强、不依赖 review 数据、不动现有 SessionSidePanel | 无 changes tab（draft 页无 review 数据，本就不需要） |

### 选定方案：B
理由：
- 符合项目"最小改动原则"
- draft 页面没有 review/diff 数据，不需要 SessionSidePanel 的 review 功能
- 只需文件浏览能力，`FileTree` 组件已足够
- 所需 context 在 `DraftProviders` 中均已提供（`FileProvider`、`LayoutProvider`、`SettingsProvider` 都是全局的）

### 具体改动

#### 1. 新增 imports
```tsx
import { createMediaQuery } from "@solid-primitives/media"
import { ResizeHandle } from "@opencode-ai/ui/resize-handle"
import FileTree from "@/components/file-tree"
import { useFile } from "@/context/file"
import { useLayout } from "@/context/layout"
import { useSettings } from "@/context/settings"
import { shouldShowFileTree } from "@/pages/session/helpers"
```

#### 2. 在组件内获取依赖
```tsx
const file = useFile()
const layout = useLayout()
const settings = useSettings()
const isDesktop = createMediaQuery("(min-width: 768px)")

// 文件树是否显示：桌面端 + 用户偏好 + 已展开
const fileTreeOpen = createMemo(
  () =>
    isDesktop() &&
    shouldShowFileTree({
      visible: settings.visibility.fileTree(),
      opened: layout.fileTree.opened(),
    }),
)
```

#### 3. 添加文件树加载副作用
参照 [session.tsx:1186-1197](file:///d:/AI/opencode/packages/app/src/pages/session.tsx#L1186-L1197) 的实现，在 new-session.tsx 中添加：
```tsx
let treeDir: string | undefined
createEffect(() => {
  const dir = sdk.directory
  if (!isDesktop()) return
  if (!layout.fileTree.opened()) return
  if (sync.status === "loading") return
  const refresh = treeDir !== dir
  treeDir = dir
  void (refresh ? file.tree.refresh("") : file.tree.list(""))
})
```

#### 4. 修改 JSX 布局
将现有 return 改为左右两栏布局：左侧主区域（输入框），右侧文件树侧边栏。

```tsx
return (
  <div class="relative size-full overflow-hidden flex flex-col">
    <div class="flex-1 min-h-0 flex gap-2 p-2">
      {/* 主区域：输入框 */}
      <div class="@container relative flex flex-col min-h-0 h-full bg-background-stronger flex-1">
        <div class="flex-1 min-h-0 overflow-hidden rounded-[10px]">
          <NewSessionDesignView>
            <SessionComposerRegion ... />
          </NewSessionDesignView>
        </div>
      </div>

      {/* 文件树侧边栏 */}
      <Show when={fileTreeOpen()}>
        <aside
          id="file-tree-panel"
          class="relative min-w-0 h-full shrink-0 overflow-hidden bg-background-stronger rounded-[10px]"
          style={{ width: `${layout.fileTree.width()}px` }}
        >
          <div class="h-full flex flex-col overflow-hidden">
            <FileTree path="" class="pt-3" onFileClick={() => {}} />
          </div>
          <ResizeHandle
            direction="horizontal"
            edge="start"
            size={layout.fileTree.width()}
            min={200}
            max={480}
            onResize={(width) => layout.fileTree.resize(width)}
          />
        </aside>
      </Show>
    </div>
  </div>
)
```

### 关键设计决策

1. **`onFileClick` 暂留空函数**：draft 页面没有文件 tab 系统（`useSessionLayout` 在无 params.dir 时不可用），点击文件暂不打开。如需点击打开文件，需后续引入 tab 管理或跳转到 session 页面。这是已知限制。

2. **复用 `layout.fileTree` 状态**：与 session 页面共享同一份持久化状态（`layout.v6`）。用户在 session 页面调整的宽度、开关状态会在 new-session 页面保持一致。

3. **不引入 `SessionHeader`**：draft 页面保持轻量，不添加标题栏。若用户需要切换按钮，可后续在输入框区域添加一个图标按钮调用 `layout.fileTree.toggle()`。

4. **`shouldShowFileTree` 复用**：与 session 页面使用同一判断函数，保证显示逻辑一致。

## 四、假设与决策

| 项 | 决策 | 理由 |
|---|---|---|
| 文件树默认是否显示 | 是（`layout.fileTree.opened` 默认 `true`） | 用户需求是"默认加载"，且 6-20 已将默认值改为 true |
| 是否提供切换按钮 | 否（暂不添加） | 最小改动；用户可通过 session 页面的按钮或快捷键控制全局开关 |
| 是否支持点击文件打开 | 否（暂不支持） | draft 页面无 tab 系统，需额外引入 `useSessionLayout`，复杂度高 |
| 是否支持 changes tab | 否 | draft 页面无 review/diff 数据 |
| 宽度是否可调 | 是 | 复用 `ResizeHandle` 和 `layout.fileTree.resize` |
